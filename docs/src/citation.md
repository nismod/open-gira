# How to cite open-gira

If open-gira contributes to work you publish, please cite it. Citing research
software is how its maintainers can show that maintenance is worthwhile, and how
readers can trace what produced a result.

## Citing the software

open-gira is archived on Zenodo with a citable DOI. The **concept DOI** below
always resolves to the latest version; Zenodo also mints a version-specific DOI
for each release, which you should prefer when you can, so your citation names
the exact version you used.

> **Concept DOI:** [10.5281/zenodo.14537079](https://doi.org/10.5281/zenodo.14537079)

The repository includes a [`CITATION.cff`](https://github.com/nismod/open-gira/blob/main/CITATION.cff)
file, so GitHub and reference managers can generate a citation for you: use the
"Cite this repository" option on the
[repository page](https://github.com/nismod/open-gira).

## Citing a data release

If you use a published open-gira *data* product rather than (or as well as) the
software, cite that data release by its own DOI. This distinguishes the data you
relied on from the code that produced it, and lets others retrieve exactly that
data. See [Data sources and licences](data/sources-and-licences.md).

## Citing upstream data

An open-gira result also rests on upstream datasets — OpenStreetMap, hazard data,
boundaries, and others — each with its own attribution expectations. Where your
publication's conventions call for it, cite those sources too;
[Data sources and licences](data/sources-and-licences.md) lists them.
